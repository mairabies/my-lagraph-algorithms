      23             : // The Leiden algorithm is a modularity-based community detection method that
      24             : // guarantees well-connected communities by introducing a Refinement phase
      25             : // between the Local-Move and Aggregation phases of the Louvain algorithm.
      26             : //
      27             : // Reference:
      28             : //   Traag, V.A., Waltman, L. & van Eck, N.J. (2019). From Louvain to Leiden:
      29             : //   guaranteeing well-connected communities. Scientific Reports 9, 5233.
      30             : //   https://doi.org/10.1038/s41598-019-41695-z
      31             : //
      32             : // Algorithm (one outer iteration = one level of the hierarchy):
      33             : //
      34             : //   Phase 1 (Local Move): Greedily assign each node to the neighboring
      35             : //     community c that maximises the score:
      36             : //       score(i->c) = T[c] - k[i] * k_comm[c] / (2m)
      37             : //     where T[c] = sum_{j in c, j!=i} A[i,j], k_comm[c] = total degree of
      38             : //     community c (excluding i), and m = total edge weight / 2 (constant).
      39             : //     This is the standard Louvain/Leiden modularity-gain formula.
      40             : //     Initial partition is induced by the Phase-1 communities of the previous
      41             : //     level (singletons on the first level).
      42             : //     Repeat until no node changes community.
      43             : //
      44             : //   Phase 2 (Refinement – key Leiden addition): Save Phase-1 communities as
      45             : //     "parent" communities.  Restart each node in its own singleton
      46             : //     sub-community.  In each local-move step a node may only join a
      47             : //     sub-community whose parent equals its own Phase-1 parent.  This ensures
      48             : //     every output community is a connected subgraph of the corresponding
      49             : //     Phase-1 community.
      50             : //
      51             : //     NOTE: Traag, Waltman & van Eck (2019) define refinement as a randomized
      52             : //     procedure (sampling moves with probability ~ exp(dQ/theta) over moves
      53             : //     with dQ >= 0).  This implementation uses the simpler greedy variant: a
      54             : //     node is moved to the neighboring sub-community that maximises dQ.  This
      55             : //     still satisfies Leiden's connectedness property in practice (every
      56             : //     refined sub-community is induced by edges within a Phase-1 community)
      57             : //     but does not provide the formal well-connectedness guarantee of the
      58             : //     randomized version.  The `seed` parameter is reserved for a future
      59             : //     randomized refinement step and is currently unused.
      60             : //     Repeat until no node changes sub-community.
      61             : //
      62             : //   Phase 3 (Aggregation): Build the coarsened graph
      63             : //       A_agg = S^T * A_cur * S
      64             : //     where S is the n_cur x K_ref membership matrix from Phase 2.  Each
      65             : //     column of S is a refined sub-community; each row of A_agg is one
      66             : //     super-node.  m is invariant under this operation.  Repeat the outer
      67             : //     loop on A_agg until no further coarsening occurs.
      68             : //
      69             : // Input:  G  – undirected graph (or directed with symmetric structure)
      70             : // Output: c_handle – GrB_Vector of INT64 where c[i] = community of node i,
      71             : //         labeled 0..K-1.
